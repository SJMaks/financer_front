# Financer - Панель личных финансов (фронтенд)

Веб-фронтенд проекта **Financer** - pet-проекта по управлению личными
финансами: учёт счетов, категорий, доходов/расходов и помесячной статистики
в современной светлой/тёмной панели управления.

> **Об этом репозитории.** Сердцем pet-проекта является его **бэкенд** -
> REST API (см. `api.financerapp.ru/swagger/index.html`). Этот репозиторий содержит только
> клиентское приложение. Поскольку основная часть pet-проекта - бэкенд,
> фронтенд был создан **с использованием Cline / mimo-v2.6-flash** - код интерфейса
> здесь написан при участии ИИ и существует в основном для демонстрации и
> проверки API.

## Стек

- React 19 + TypeScript (strict) + Vite
- Redux Toolkit - глобальное клиентское состояние (auth/JWT, тема, язык, тосты)
- React Query (`@tanstack/react-query`) - всё состояние сервера с кешированием
  и инвалидацией
- React Router v7 - маршрутизация с защитой (protected/guest) и разделением
  кода на уровне маршрутов
- Tailwind CSS v4 - стилизация, классовый dark mode, «стеклянные»
  (frosted) поверхности
- Recharts - графики доходов/расходов/прибыли
- Axios - HTTP-слой с JWT-заголовком и централизованной обработкой 401
- lucide-react - иконки
- Встроенная i18n - словари на английском и русском (проверяются на этапе
  компиляции), выбранный язык сохраняется между перезагрузками

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # проверка типов + production-сборка
npm run lint
npm run preview  # локальный предпросмотр production-сборки
```

Адрес бэкенда настраивается в файле `.env`:

```
VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1
```

Бэкенд должен быть запущен и доступен по этому адресу (если переменная не
задана, клиент использует `http://localhost:8000/api/v1`).

## Возможности

- **Авторизация** - вход/регистрация, JWT хранится в `localStorage`,
  защитные маршруты (guards) для защищённых и гостевых страниц.
- **Дашборд** - сводные карточки (баланс, доход, расход, прибыль), график
  доходов/расходов и последние операции.
- **Счета** - список, создание/редактирование/удаление, страница детали
  счёта с отдельными представлениями операций и статистики.
- **Операции** - страница с серверной пагинацией, фильтрацией
  (`type`, `category_id`, `min_date`, `max_date`) и сортировкой
  (`sort`, `order`), хранящимися в URL, диалоги создания/просмотра/редактирования.
- **Категории** - управление категориями доходов/расходов с визуальным
  выбором иконки и цвета.
- **Статистика** - помесячные графики доходов/расходов/прибыли, общая и по
  конкретному счёту.
- **Профиль** - изменение полного имени и валюты, удаление аккаунта с
  подтверждением.
- **UI/UX** - светлая/тёмная тема (сохраняется), локализация (EN/RU), тосты,
  адаптивная вёрстка (боковое меню на десктопе + выдвижной ящик/верхняя
  панель на мобильных), скелетоны загрузки, состояния пустоты и ошибки.

## Архитектура

```
src/
  app/         роутер (разделение кода на уровне маршрутов)
  components/  общий UI-кит (Button, Modal, ConfirmDialog, ...) + guards
  features/    auth, dashboard, accounts, categories, operations,
               statistics, profile (страницы, формы, React Query хуки)
  hooks/       общие хуки (форматирование денег, типы операций)
  i18n/        словари en/ru + useTranslation
  layouts/     оболочка авторизованного пользователя (сайдбар на десктопе,
               выдвижной ящик на мобильных)
  services/    экземпляр Axios, API-модули по доменам, хелперы ошибок
  store/       Redux слайсы (auth, ui) + типизированные хуки
  types/       DTO, точно повторяющие swagger.json
  utils/       форматирование + вспомогательные функции для операций
```

Ключевые принципы:

- JWT хранится в `localStorage`, подставляется как `Authorization: Bearer
  <JWT>`; любой 401 на аутентифицированном запросе очищает сессию и
  перенаправляет на `/login`.
- Выход из аккаунта выполняется только на фронтенде (в API нет эндпоинта
  logout): токен удаляется, состояние auth в Redux сбрасывается, кеш React
  Query очищается.
- Мутации инвалидируют затронутые кеши React Query (счета, категории,
  операции, статистика), поэтому интерфейс всегда синхронизирован.
- Операции используют серверную пагинацию (`limit`/`offset`), фильтрацию
  (`type`, `category_id`, `min_date`, `max_date`) и сортировку
  (`sort`, `order`) через параметры URL.
- `version` всегда отправляется при обновлениях для контроля оптимистичных
  блокировок.
- Разрушающие действия (удаление счёта/категории/операции/профиля) требуют
  явного диалога подтверждения.
- Валюта пользователя (`currency` из `/users/me`) отображается рядом с
  каждым денежным значением; её можно изменить в профиле рядом с полным
  именем.
- Тексты интерфейса полностью локализованы (английский/русский) с
  переключателем языка в сайдбаре, верхней панели мобильной версии и на
  страницах авторизации; даты и числа форматируются в соответствии с
  активной локалью.
